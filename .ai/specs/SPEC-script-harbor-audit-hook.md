# Script Harbor audit hook

Status: Implemented. Owner: session author. Independent advisor review completed before implementation and adversarial runtime review completed after integration. Scope: new public `MarcinWalendowski/script-harbor` repository.

## TLDR
Inventory scripts from production URLs or built HTML; save exact bytes; review with OpenRouter, Claude, OpenAI/Codex or exported JSON; require explicit human approval; pin and rehost approved bytes; fail CI on drift. A review is evidence, never a safety certificate.

## Problem
An externally hosted script can change after a deploy and inherit the page's privileges. User-provided motivation is the reported Polymarket/DebugBear incident, linked in README with source-qualified wording. Version strings and HTTP cache headers do not pin bytes.

## Solution

Move the existing full explanations and commands into `docs/technical-guide.md`, retaining working relative links to integrations, security, verification and license. Keep the qualified Polymarket/DebugBear motivation visible with fuller attribution in the guide. The diagram and prompt must preserve explicit human approval, hash-based review reuse and static/SSR limitations; no claim that installation alone protects a site. Verify Markdown links, XML validity, browser rendering at desktop/mobile widths, and that all existing technical sections survive the move. No CLI or runtime behavior changes.
Node >=22 TypeScript CLI. Commands: `scan`, `review`, `approve`, `vendor`, `check`, `protect`, `init`, `export-review`, `import-review`. `scan --url URL` (repeatable) and/or `--dir DIR --origin URL` inventories HTML script src and modulepreload links. Remote URLs, including same-origin URLs when scanning live sites, are captured; built same-origin files already in the bundle are inventoried as local and need no rehosting. `--runtime` optionally observes script responses using a fresh Playwright browser context; no personal profile, secrets, storage state or interactions. Default static scan never executes downloaded JS. Coverage is explicitly bounded by input pages and observation window; no claim to discover all possible code paths.

`review --provider openrouter|claude|codex --model MODEL` uses tool-free HTTP requests (Codex means OpenAI Responses API, not a subscription login). API keys from environment only. Default review does not approve. `approve HASH --reviewer NAME --reason TEXT --allow-rehost` explicitly accepts a reviewed hash and confirms redistribution/relocation responsibility. Modules, loaders and origin-sensitive scripts are blocked from automatic relocation when detected; do not silently bundle a broken dependency graph. There is no auto-approve flag. Export/import supports review with any external LLM, including Claude Code and Codex CLI.

## Architecture
- `types.ts`, `store.ts`: strict persisted schemas, SHA-256 source store, SHA-384 SRI, atomic writes, review fingerprints and approvals.
- `network.ts`, `discovery.ts`: HTTP(S) GET only, DNS-pinned public addresses, redirect revalidation, no credentials/cookies, response timeout/byte/script caps, real HTML parser and browser capture.
- `analysis.ts`, `providers.ts`: deterministic capability hints plus full-source LLM JSON review; suspicious script text treated as data, no tools; bounded inputs, retries with jitter for transient API errors, no truncation accepted as full review.
- `pipeline.ts`, `rewrite.ts`, `report.ts`: orchestration, local hash validation, fail-closed gates, exact-byte vendoring, surgical HTML rewrite preserving attributes, JSON/Markdown reports and JSONL local audit events.
- `cli.ts`, `integrations.ts`: CLI and host/framework setup.

State `.script-harbor/`: `manifest.json`, `sources/<sha256>.js`, `reviews/<fingerprint>.json`, `approvals.json`, `report.json`, `report.md`, `events.jsonl`. Review fingerprint covers content hash, provider, model, prompt version, policy version. Approval binds hash + review fingerprint + human identity/reason; a changed selected review policy requires approval again. Invalid schema, missing/tampered source, unknown hash, partial fetch, malformed/truncated review, limit exceeded, changed script, unsupported rewrite => nonzero exit; no automatic trust on first use. Cache skips LLM calls, never skips integrity checks. Build check uses committed source and approval offline; optional live check refetches upstream to detect drift. Manifest/approvals are version-controlled trust inputs, protected through normal Git review, not cryptographically signed attestations.

## Data Models
Advisor decisions: hash and vendor decompressed HTTP response bytes; decode UTF-8 strictly for review. Runtime routes all GETs through the DNS-pinned fetcher, blocks non-GETs, service workers and WebSockets, and records failures. `eligible` means no blocker detected, not guaranteed relocatable. Plan all changes before staging/writing; validate every page before modifying any HTML, with rollback on write errors. Reject cross-origin base URLs and ambiguous duplicate attributes. Offline checks never claim to establish upstream freshness. Preserve stale state only as history, never as a successful new scan.

Contracts are declared in `src/types.ts` before lanes start. Artifact: `url`, `finalUrl`, `sha256`, `sri`, `bytes`, `contentType`, `pages[]`, `kind` (classic/module/preload/runtime), `thirdParty`, `relocation` (eligible/manual), `relocationReasons[]`. Manifest schemaVersion=1, createdAt, origins, artifacts, localScripts, coverage {mode,pages,limitations}, errors. Review: schemaVersion, fingerprint, sha256, provider, model, promptVersion, policyVersion, createdAt, verdict (low-risk/review-required/high-risk), summary, findings [{severity,category,evidence,explanation}], relocation {safe:boolean,reason}. Approval: sha256, fingerprint, reviewer, reason, approvedAt, allowRehost. Model output cannot supply trusted hashes, approvals, paths or commands.

## API Contracts
Environment: OPENROUTER_API_KEY, ANTHROPIC_API_KEY, OPENAI_API_KEY, SCRIPT_HARBOR_MODEL, SCRIPT_HARBOR_PROVIDER. Explicit CLI flags override defaults. `check` validates all captured artifacts and approvals; `protect --dir DIR --origin URL` scans freshly emitted HTML, checks saved approvals, vendors exact cached approved bytes and rewrites tags; fails before HTML mutations on any problem. `init --framework astro|vite|next|nuxt|sveltekit --origin URL` preserves existing build command as `build:unprotected` and sets build to run it then `script-harbor protect`; idempotent, refuses conflicting helper scripts. Defaults: dist, dist, out, .output/public, build respectively. Next/Nuxt/SvelteKit require static output; SSR documented with `vendor --public-dir public` and explicit source mapping, no promise of transparent SSR rewrite. Support Vercel, Netlify, Cloudflare Pages, GitHub Pages and generic static CDN through the same command, no vendor service deployment or registry publish in scope.

## Risks
LLMs and heuristics miss malicious logic; approval and pinning prevent unreviewed change, not malicious approved code. Dynamic loaders may fetch unpinned descendants; mark manual and fail automatic relocation. CSP and SRI are defense in depth, report recommended policy but do not silently alter app behavior. Rehosting may violate licenses or break telemetry/consent/origin assumptions; retain bytes/notices and require explicit acknowledgement. Browser discovery executes untrusted code and belongs on a disposable runner; fresh context is not OS isolation. Do not run incident payloads here. Local state is trusted developer input; secrets and generated audit evidence stay out of this public tool repository. Bounded budgets: default 100 scripts, 5 MiB/script, 20 s fetch, 200k source chars per model request; oversize fails closed; no unlimited retries/crawling. Local events only, no outbound telemetry.
